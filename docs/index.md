# 从 Markdown 到 GitHub Pages

> 一次推送，自动构建；把零散笔记整理成随时可访问的技术文档。

欢迎来到我的技术文档站！这个项目以 **MkDocs Material** 组织 Markdown 页面，以 **GitHub Actions** 执行构建和发布，以 **GitHub Pages** 提供公开访问入口。

## 这个网站能做什么？

- **集中展示知识**：将首页、项目介绍、使用指南和 API 示例放在同一个导航结构中。
- **保留版本历史**：每次内容变更都会形成 Git 提交，方便追溯和比较。
- **减少重复劳动**：推送特定文件到 `main` 后，工作流自动重新构建与发布。
- **练习故障定位**：出现错误时，可根据 Actions 的具体步骤和日志定位原因。

## 从源码到网站的路径

```text
编写 docs/*.md
      |
      v
提交并推送到 main
      |
      v
GitHub Actions：安装依赖 → mkdocs build --strict
      |
      v
site/（生成的 HTML、CSS 等静态资源）
      |
      v
GitHub Pages：公开网站
```

这条链路中，**`docs/` 是手动维护的源码，`site/` 是自动生成的构建产物**。修改页面时，应修改 `docs/` 下的文件，而不是直接编辑 `site/`。

## 小型实践任务

完成首次部署后，可以尝试在此页面增加一句自己的实验记录，再推送到 `main`：

```markdown
自动部署验证：这是我第二次推送后新增的内容。
```

若这句话出现在公开网站上，且 Actions 中出现由 `push` 触发的新运行记录，就能构成“自动更新”的一项证据。
